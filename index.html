Architecture & Core

Ключевые преимущества ядра

Key Architecture Advantages

Спроектирован с нуля для максимальной энергоэффективности, предсказуемого выполнения без пауз GC и глубокого аппаратного доступа.

Designed from scratch for peak throughput, zero-GC pause predictability, and direct bare-metal hardware access.

Win32 PE & Linux ELF упаковщик

Win32 PE & Linux ELF Packer

Сборка программ в самостоятельные бинарные исполняемые файлы Win32 PE (.exe) и самораспаковывающиеся ELF-бинарники для Linux. Байт-код компонуется в тело загрузчика (`-emit-exe`), работая автономно без внешних рантаймов, Node.js или Python.

Compiles programs into standalone Win32 PE binary executable files (.exe) and self-extracting Linux ELF binaries. Bytecode is packed directly with the native runner (`-emit-exe`), running without external runtime dependencies.

Win32 PE & Linux ELF -emit-exe Zero Runtime Dependency

Direct-Threaded VM & JIT

Direct-Threaded VM & JIT

Прямая диспетчеризация инструкций через Labels-as-Values (`computed goto` / `goto *dispatch_table[op]`). Полное устранение циклов `while(switch)` и накладных расходов ветвления с аппаратным JIT-ускорением горячих циклов x86_64.

Instruction dispatch via Labels-as-Values (`computed goto` table pointers). Completely eliminates `switch` loops and branch overhead, paired with a native x86_64 JIT compiler for critical hot loops.

Computed Goto x86_64 SSE2 JIT Opcode Fusion

Arena Allocator & NaN-Boxing

Arena Allocator & NaN-Boxing

Выделение памяти со сдвигом указателя (bump-pointer) без фрагментации ОЗУ и освобождением целых пулов в O(1). Все базовые значения упакованы в 64-битный формат IEEE 754 (ровно 8 байт), снижая нагрузку на L1-кэш процессора в 2 раза.

Bump-pointer linear memory allocation with zero fragmentation and instant O(1) pool release. All primitives fit into a flat 64-bit IEEE 754 NaN-box (strictly 8 bytes), halving CPU L1 cache bandwidth pressure.

Bump Pointer 8-Byte Values C-ABI Alignment

Кроссплатформенность & Freestanding

Cross-Platform & Freestanding

Универсальный скрипт `install.sh` для дистрибутивов Linux и графический `setup.exe` для Windows. Режим сборки ядра без libc (`--freestanding`) через GrassHAL для микроконтроллеров и ОС, прямое чтение MMIO/портов и барьеры памяти.

Universal Linux `install.sh` and graphical Windows `setup.exe`. Independent freestanding mode without libc (`--freestanding`) via GrassHAL for microcontrollers, direct MMIO / Port I/O, and hardware barriers.

Linux + Windows GrassHAL MMIO & Port I/O

tone(freq_hz, duration_ms, volume) Генерация чистой синусоидальной гармоники заданной частоты со сглаживанием фронтов.
sound_play(path, loop), sound_stop() Нативное воспроизведение аудиофайлов (.wav, .mp3, .ogg, .mid) с нулевыми зависимостями.
sound_pause(), sound_resume(), sound_volume(vol) Управление воспроизведением трека и громкостью от 0 до 100%.
beep(freq_hz, duration_ms), sound_is_playing() Аппаратный короткий сигнал спикера и проверка статуса воспроизведения.
The Evolution & v4.1

Дорожная карта ядра: от v4.0 к релизу v4.1

Core Roadmap: v4.0 Evolution to v4.1 Release

Ключевые вехи эволюции языка GrassGreen: архитектура ядра v4.0 и масштабный релиз v4.1 с векторным GUI VD+, аудио-движком и кроссплатформенным Linux.

Key evolution milestones of GrassGreen: v4.0 core architecture and major v4.1 release with VD+ GUI, !audio! engine, and Linux support.

п. 1

Минимальный JIT-компилятор

Minimal x86_64 JIT Compiler

Complete

Генерация нативных машинных инструкций x86_64 для критических горячих участков байт-кода. Выделение страниц PAGE_EXECUTE_READWRITE, работа с SSE2 регистрами (xmm0, xmm1), соответствие Microsoft x64 ABI и флаг компилятора `--jit` (авто-включение при `-O3`).

Generates native x86_64 machine code for hot execution loops using SSE2 registers and Microsoft x64 ABI calling conventions with `--jit` CLI switch.

п. 2

Динамические массивы: `array`

Dynamic Arrays: `array`

Complete

Векторные структуры динамического и фиксированного размера с быстрой индексацией `arr[i]`, методами `items.push(val)`, `items.pop()` и встроенной функцией длины `len(items)`.

Vector structures with rapid `arr[i]` indexing, push/pop operations, and O(1) length inspection via `len()`.

п. 3

Автодополнение (IntelliSense) по всем библиотекам

IntelliSense Snippets Across All Libraries

Complete

Подсказка встроенных функций, методов и констант библиотек в реальном времени через богатый набор сниппетов: `main`, `gout`, `gin`, `fn`, `struct`, `thread`, `async`, `mutex`, `mmio_read`, `mmio_write`, `inb`, `outb`, `barrier`, `gfx_app`.

Real-time completions across all 18 standard libraries in VS Code via comprehensive snippets schema.

п. 4

Подсветка синтаксиса по всем библиотекам

TextMate Syntax Highlighting

Complete

Разработка TextMate грамматики (`syntaxes/grassgreen.tmLanguage.json`) для всех ключевых слов, директив `!module!`, структур, типов, потоков `gout`/`gin` и операторов сдвига `<<`/`>>`.

TextMate grammar covering all tokens, directives, types, stream operators, and library calls.

п. 5

Интеграция в системный PATH и графический установщик

System PATH Integration & Win32 Installer

Complete

Полноценный автономный GUI инсталлятор `setup.exe` в темной теме GrassGreen. Упаковка `grg.exe`, ассоциации расширений `.grass` и `.gdb`, тихий режим (`setup.exe /silent`), авто-запись в реестр HKCU/HKLM PATH с широковещательным WM_SETTINGCHANGE.

Standalone dark-themed setup.exe with silent mode (`setup.exe /silent`), file associations, and instant PATH broadcast.

п. 6

Перевод языка в режим Freestanding

Freestanding Bare-Metal Mode

Complete

Полная независимость от стандартных библиотек C++ (работа без libc / libc++ / iostream через модуль аппаратной абстракции GrassHAL). Ядро готово к выполнению в bare-metal окружении, микроконтроллерах и загрузчиках ОС.

Zero dependency on libc or iostream via GrassHAL abstraction layer, ready for OS loaders and embedded targets.

п. 7

Табличная диспетчеризация (Dispatch Table)

Table-Based Dispatch (Dispatch Table)

Complete

Уход от медленного цикла `while(switch)`. Массив прямых указателей на обработчики опкодов для мгновенного перехода между инструкциями виртуальной машины.

Replaces branch-heavy switch constructs with a direct array of opcode function pointers.

п. 8

Склейка AST и разрешение зависимостей (Import Pass)

AST Merging & Dependency Resolution (Import Pass)

Complete

Разрешение зависимостей на этапе построения дерева с рекурсивным обходом, канонической нормализацией путей, семантикой `#pragma once` (защита от циклов и ромбовидных импортов) и поддержкой RamFS.

Recursive dependency resolution, path canonicalization, `#pragma once` diamond protection, and RamFS support.

п. 9

Bytecode Layout & Fusion Optimizer

Bytecode Layout & Fusion Optimizer

Complete

Многопроходный оптимизатор: Opcode Fusion (слияние цепочек констант и арифметики в `OP_ADD_CONST`, инкрементов в `OP_INC_VAR`), Constant Folding, Dead Code Elimination и Jump Relocation. Ускорение циклов в 2.6 раза при `-O3`.

Multi-pass optimizer: opcode fusion, constant folding, dead-code elimination, and jump relocation delivering 2.6x loop speedup.

п. 10

Пользовательские структуры: `struct`

User Structures: `struct`

Complete

Синтаксис объявления составных типов данных (`struct Player { hp: u32, x: u64 }`) с расчетом смещения полей в байтах на этапе компиляции и прямым доступом через точку.

Custom compound types with compile-time byte offset calculations and dot-notation access.

п. 11

Настоящий импорт файлов: `import` / `include`

Modular File Imports: `import` / `include`

Complete

Поддержка полноценных модулей на самом языке `.grass`: синтаксисы `import "module.grass";`, `include "module";`, `#include <module.grass>` со сквозным вызовом структур и функций из `main()`.

Write re-usable modules directly in `.grass` files with seamless cross-module function and struct calls.

п. 12

Многопоточность: `thread` / `async`

Concurrency: `thread` / `async`

Complete

Асинхронные задачи и системные потоки операционной системы: `thread(fn, args)`, `thread_join`, `async fn();`, мьютексы `mutex_create/lock/unlock` и разделяемая среда `GrassSharedEnv` с защитой от гонок.

Native OS threads, async dispatch, thread synchronization joins, mutex primitives, and shared race-protected memory.

п. 13

Официальное расширение для Visual Studio Code

Official Visual Studio Code Extension

Complete

Собранный установочный пакет `.vsix` (`grassgreen-4.0.0.vsix`): полная TextMate подсветка, иконки для файлов `.grass` и `.gdb`, сниппеты кода и поддержка горячих клавиш сборки.

Packaged `grassgreen-4.0.0.vsix` extension bundle containing full language grammar, icons, and snippets.

п. 14

Представление значений через NaN-Boxing

Value Representation via NaN-Boxing

Complete

Упаковка чисел, булевых флагов, указателей и дескрипторов в плоский 64-битный формат IEEE 754 (ровно 8 байт). Двукратное сокращение нагрузки на L1-кэш процессора и ускорение вызовов функций.

Strict 8-byte IEEE 754 representation for numbers, booleans, pointers, and objects with 2x cache efficiency.

п. 15

Аллокатор памяти: Arena Allocator

Arena Allocator (Bump Pointer)

Complete

Линейное выделение непрерывного пула памяти под AST и байт-код со сдвигом указателя. Мгновенное освобождение памяти модулей в O(1) без фрагментации, вызовов malloc/free и утечек ресурсов.

Continuous memory pool allocation with pointer increments and zero-fragmentation O(1) deallocation.

п. 16

Диспетчеризация через Labels-as-Values

Labels-as-Values Dispatch (Computed Goto)

Complete

Механизм `goto *dispatch_table[op]` для прямого прыжка из конца текущей инструкции в начало следующей. Процессор использует таблицу предсказания переходов без задержек центрального цикла.

Direct `goto *dispatch_table[op]` jumps eliminating central branch-prediction bottlenecks in VM execution.

п. 17

Оптимизация расположения структур: C-ABI Data Alignment

C-ABI Data Alignment

Complete

Выравнивание полей структур по естественным границам адресов (1, 4, 8 байт). 100% совместимость компоновки памяти структур с нативными драйверами и кодом на C/C++.

Exact 1, 4, and 8-byte field alignment conforming strictly to native C-ABI struct layouts.

п. 18

Аппаратный доступ к физической памяти: MMIO и `volatile`

Hardware MMIO & Volatile Access

Complete

Прямое чтение и запись физических адресов памяти (`mmio_read8..64`, `mmio_write8..64`), порты x86 (`inb`/`outb`), квалификатор `volatile` и барьеры сериализации памяти mfence/lfence/sfence.

Direct MMIO read/writes, x86 Port I/O instructions, `volatile` variable qualifiers, and hardware memory fence instructions.

п. 19

Ребрендинг экосистемы: `G&G`

Ecosystem Rebranding: `G&G`

Complete

Официальное сокращённое наименование проекта: **G&G** (*Grass & Green*). Бинарник компилятора в терминале — **`grg`** (в среде Windows — `grg.exe` / `grassc.exe`).

Unified ecosystem naming: G&G with primary compiler CLI binary command `grg`.

Comprehensive flags: `-o`, `-c`, `-emit-exe`, `-O0..-O3`, `--dump-ast`, `-S`, `--time`, `--freestanding`, `--ru`/`--en`.

VD+ Vector GUI Suite (Video Graphics Plus)

Full shift to CSS-grade vector compositing. High-DPI `auto_size_display()` (2K/4K), DWM corner rounding `border-radius-app(r)`, header styles, `tab/switch` system, synchronized `clock()`, and background `particles()`.

Native Audio Engine `!audio!` & PCM Wave Synth

Procedural 44.1 kHz PCM waveform synthesis (sine, square, saw, triangle, noise), frequency tones `tone()`, system beeps `beep()`, and zero-dependency audio playback (.wav, .mp3, .ogg).

Cross-Platform Linux & `install.sh` Installer

Универсальный скрипт `install.sh` с автоопределением менеджеров пакетов (pacman, apt, dnf, zypper, apk, xbps), компиляция ядра под Linux через `build.sh` (C++20, `-pthread`) и сборка в самораспаковывающиеся ELF-бинарники (`grg -emit-exe`).

Universal `install.sh` supporting all major Linux distributions (Arch, Ubuntu, Fedora, Alpine), Linux compiler build via `build.sh` (C++20, `-pthread`), and self-extracting ELF executable generation.
